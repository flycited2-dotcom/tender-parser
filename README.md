# Парсер закупок и тендеров

Парсер ищет публичные актуальные закупки по заданным категориям, фильтрует их по регионам, сумме от 30 000 рублей и стоп-темам, сохраняет историю в SQLite и выгружает Excel.

## Запуск

Двойной клик по файлу:

```text
Запустить_парсер.bat
```

После завершения откроется `exports/latest.html`.

Быстрые кнопки:

- `Запустить_локальные_выгрузки.bat` - обработать только `imports/` и `documents/`, без сетевых площадок.
- `Диагностика_RTS.bat` - проверить только RTS-Tender и записать его health/report.
- `Открыть_RTS_кабинет_Chrome.bat` - открыть отдельный Chrome-профиль для ручного входа в RTS.
- `Собрать_RTS_кабинет.bat` - собрать текущую видимую выдачу RTS-кабинета через `--profile rts-cabinet`.
- `Автосбор_RTS_кабинета.bat` - запустить автосбор: окно висит в фоне, вы просто листаете выдачу RTS в Chrome, каждая страница добавляется в накопитель сама, а в углу страницы RTS виден бейдж «Накопитель RTS: N строк». Остановить - Ctrl+C или закрыть окно. Если открыть вкладку поиска `rts-tender.ru/poisk`, автосбор сохранит ее вёрстку в `diagnostics/` - по этим снапшотам настраивается парсер поиска по всем ЭТП.
- `Добавить_страницу_RTS.bat` - разово добавить текущую видимую страницу RTS-кабинета в накопитель (ручная альтернатива автосбору; дубли по номеру закупки не создаются).
- `Отчет_по_накопленному_RTS.bat` - прогнать все накопленные страницы RTS через общий отчет (`--profile rts-accumulated`).
- `Поиск_RTS_другие_площадки.bat` - открыть сохраненный поиск RTS по всем ЭТП в рабочем Chrome-профиле и сразу запустить автосбор: листаете результаты поиска, карточки с любых площадок (ЕАТ, B2B и др.) сами падают в тот же накопитель с источником `rts-poisk`.

## Ручные выгрузки и документы

Для максимального охвата можно подмешивать выгрузки из личных кабинетов и площадок без отдельной интеграции:

- положите CSV/XLSX/XML-файлы в папку `imports/`;
- шаблоны лежат в `docs/templates/import_template.csv`, `docs/templates/rts_export_template.csv` и `docs/templates/sevastopol_zmo_import_template.csv`;
- поддерживаемые колонки: название, ссылка, номер, заказчик, регион, сумма, срок подачи, дата публикации, источник, описание;
- положите доказательства в папку `documents/`: TXT, CSV, XML, JSON, HTML, XLSX, DOCX, PDF;
- при запуске парсер прочитает `imports/`, добавит источник `ImportFolderSource` в `run_report.json`, затем проверит `documents/` и заполнит поля `detail_status`, `document_matches`, `delivery_region_evidence`, `source_confidence`.

PDF читается по текстовому слою; если это скан-картинка без распознанного текста, его нужно предварительно прогнать через OCR или сохранить как TXT. Реальные кабинетные выгрузки и документы не коммитятся: `imports/` и `documents/` добавлены в `.gitignore`.

## Автозагрузка документов ЕИС

Для новых подходящих закупок ЕИС парсер умеет открыть вкладку «Документы» и сохранить публичные вложения в `downloads/eis-zakupki/<номер закупки>/`. Это работает и для карточек РосТендера, если их ссылка на ЕИС подтверждена; для 223-ФЗ GUID вкладки документов извлекается из публичной карточки. В локальном `.env` включите:

```text
DOWNLOAD_TENDER_DOCUMENTS=1
DOWNLOAD_MAX_TENDERS=10
DOWNLOAD_MAX_DOCUMENTS_PER_TENDER=10
DOWNLOAD_MAX_FILE_MB=25
```

Повторно существующие файлы не скачиваются. Итог каждого запуска записывается в `downloads/download_report.json`. Ссылки принимаются только из публичного файлового хранилища `zakupki.gov.ru`, проверка TLS не отключается.

## Уведомления Telegram

Каждый запуск всегда создаёт локальный текст `exports/notification.txt`. Для Telegram заполните в `.env`:

```text
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=
TELEGRAM_MAX_ITEMS=10
```

Если Telegram временно недоступен, новые карточки остаются в SQLite-очереди и повторно отправляются при следующем запуске. Токен не выводится в консоль и не попадает в Git.

При `TELEGRAM_SEND_DAILY_REPORT=1` бот каждый день присылает контрольную сводку даже при нуле новых закупок. При `TELEGRAM_SEND_EXCEL=1` следом прикладывается свежий Excel. Кнопки и команды обслуживает отдельная фоновая задача:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Настроить_Telegram_бот.ps1
```

- `/status` — состояние последнего запуска;
- `/report` — последний Excel;
- `/fresh` — немедленно запустить новый сбор.
- `/price шкаф архивный` — найти подходящие позиции и дилерские цены в локальных прайсах поставщиков.

Обработчик команд должен быть единственным процессом, который вызывает Telegram `getUpdates` для этого токена. Если тот же бот ещё работает на другом VPS, старую службу нужно сначала остановить; обычная отправка ежедневных сообщений при этом конфликтов не создаёт.
После остановки старой службы включите `TELEGRAM_COMMANDS_ENABLED=1` в `.env.local` и активируйте задачу `Tender Parser Telegram Bot`.

## Постоянный Google-реестр

Google-таблица содержит вкладки `Сводка`, `Новые сегодня`, `Все актуальные`, `Мой отбор`, `Потенциальные заказчики`, `Архив` и `История запусков`. `Сводка` показывает KPI и здоровье каждой площадки. В реестре раздельно доступны первоисточник, исходная карточка агрегатора, фактическая ЭТП и `Документы`; для 44-ФЗ ссылка на РТС ведёт сразу в процедуру с номером извещения. Строки обновляются по ключу `источник+номер`; значения `Мой выбор` и `Комментарий` сохраняются между запусками. Исчезнувшие после успешного опроса карточки переходят в архив, но при CAPTCHA, 429, тайм-ауте или частичном ответе прежний успешный снимок источника сохраняется с предупреждением.

Вкладка `Потенциальные заказчики` автоматически собирает государственных, муниципальных и бюджетных заказчиков из четырёх целевых регионов. Ручные контакты и статусы проверки сохраняются между запусками. Служебные e-mail и телефоны следует переносить только с официальных страниц; статус `Проверен` означает проверку данных, но не согласие на рекламную рассылку.

Для автоматической записи нужен JSON-ключ сервисного аккаунта Google. Таблицу необходимо открыть сервисному аккаунту с ролью редактора, затем выполнить:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Настроить_Google_Sheets.ps1 -CredentialsFile "C:\путь\к\ключу.json"
```

Ключ копируется в игнорируемую Git папку `secrets/`. Если Google ещё не подключён, основной парсинг и Telegram продолжают работать, а сводка показывает, что таблица ожидает подключения.

## Ежедневный сбор

Для фонового запуска без окна есть `run_tender_parser_silent.bat`: лог будет записываться в `logs/daily.log`.

Чтобы зарегистрировать ежедневную задачу Windows на 08:00, один раз запусти PowerShell из папки проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Настроить_ежедневный_запуск.ps1
```

По умолчанию ежедневный запуск использует профиль `fast`: он включает ЕИС, текущий JSON API ГПБ и другие быстрые публичные источники, но не ждёт captcha-источники RTS. Полный режим можно включить явно:

Независимые площадки внутри `fast` опрашиваются ограниченно параллельно (до четырёх одновременно). Для каждой площадки сохраняются собственные паузы и лимиты запросов; ускорение достигается за счёт одновременной работы разных источников, а не учащения обращений к одному сайту.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Настроить_ежедневный_запуск.ps1 -Profile full
```

Другое время задается так:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Настроить_ежедневный_запуск.ps1 -Time "07:30"
```

Задача Windows работает от системной учётной записи `SYSTEM`, поэтому открытый пользовательский сеанс не требуется. Она запускается при первой возможности, если компьютер был выключен в назначенное время, и ждёт доступного сетевого подключения. Дополнительно она проверяет пропущенный запуск через две минуты после входа пользователя в Windows. Успешный запуск за расчётные сутки повторно не выполняется, а параллельные экземпляры блокируются.

При критической ошибке сбора или Telegram задача повторяется до трёх раз с интервалом 15 минут. Неотправленные Telegram-карточки остаются в SQLite-очереди и уходят при успешном повторе. Состояние предохранителя хранится в `data/scheduler_state.json`, его журнал — в `logs/scheduler.log`.

## Настройка словаря без программирования

Основные настройки поиска находятся в `config/Настройки_поиска.xlsx`. Парсер перечитывает этот файл перед каждым запуском. В нём можно:

- добавлять категории и ключевые слова;
- включать и отключать поисковые запросы;
- добавлять стоп-слова;
- выбирать регионы;
- менять минимальную сумму.

Для отключения строки выберите `Нет` в столбце `Активно`. Если файл отсутствует или повреждён, запуск не падает: используется встроенный словарь, а причина выводится в лог.

В базовом профиле приоритетны Республика Крым, Севастополь, Запорожская и Херсонская области. Учитываются также города внутри этих регионов и явные формулировки «адрес/место поставки»; поэтому адрес заказчика из другого субъекта не перекрывает доставку в целевой регион. Нецелевые города и субъекты отсекаются, а карточки глобальных B2B-выдач без подтверждённого целевого региона остаются в истории как исключённые и не засоряют активный реестр.

## Результаты

- `data/tenders.db` - локальная история закупок.
- `exports/tenders_YYYY-MM-DD.xlsx` - Excel с листами `Дашборд`, `Новые`, `Горячие`, `На проверку`, `Широкий хвост` и `Отсеянные`. Дашборд показывает KPI, разбивку по источникам и категориям с графиками, скоро закрывающиеся, топ причин отсева, топ горячих и здоровье источников. Новизна тендера определяется по базе `data/tenders.db` (ключ площадка+номер): впервые увиденные и впервые ставшие подходящими получают метку `🆕` в колонке `новый` на всех листах и попадают на лист `Новые`; повторно спарсенные вчерашние тендеры не дублируются и метку не получают. Колонки `мой_выбор` и `комментарий` переносятся из предыдущего файла автоматически, отмеченные ✅/🤔 собираются на листе `Мой отбор`. Листы данных: автофильтр по всем колонкам, закрепленные приоритет/срок/название, раскраска строк по приоритету, подсветка `дней_до_срока` (красный - 2 дня и меньше, желтый - неделя), кликабельные названия, суммы и сроки как настоящие числа/даты для сортировки, колонка `мой_выбор` с выпадающим списком (Беру / Думаю / Мимо) и `комментарий` для ручного отбора.
- `exports/latest.json` - JSON для будущей CRM с подходящими закупками и кандидатами на ручную проверку, включая поле `review_priority`.
- `exports/latest.html` - человекочитаемый браузерный отчет для ручного просмотра: приоритеты, ссылки, регион/сумма/срок, evidence и здоровье источников.
- `exports/new_tenders.json` - только впервые увиденные подходящие закупки и кандидаты на проверку; основной файл для ежедневной CRM-очереди, отсортированный по приоритету.
- `exports/notification.txt` - краткая человекочитаемая сводка новых закупок для уведомления.
- `exports/run_report.json` - здоровье источников: статус, число карточек, время запроса, ошибка или причина пропуска.
- `exports/supplier_matches.json` - закрытая локальная подборка товаров поставщиков для актуальных тендеров: артикул, модель, дилерская/розничная цена и исходный лист прайса.
- Для подходящих карточек РосТендера отчёты отдельно показывают внутренний номер/ссылку агрегатора и раскрытые поля первоисточника: официальный номер, ЕИС, исходную ЭТП, закон, способ и уверенность сопоставления. Колонка «Прямая ссылка» появляется только после подтверждения карточки официальным поиском или самой площадкой. Неподтверждённый номер остаётся в колонке «Номер на площадке» как косвенный признак, но не маскируется под рабочую ссылку.
- JSON и Excel содержат enrichment-поля: `detail_status`, `document_matches`, `delivery_region_evidence`, `source_confidence`.
- Публичные источники: ЕИС `zakupki.gov.ru`, ЭТП ГПБ, Росэлторг, Заказ РФ, Сбербанк-АСТ, Tender.Pro API, Торги82 JSON, официальная витрина малых закупок Республики Крым, B2B-Center, `rostender.info` и RTS-market с диагностикой по каждому endpoint.
- ЕАТ/Березка подключается как интеграционный API-источник при наличии токена из личного кабинета.
- Исследование следующих ЭТП для подключения: `docs/etp_source_research_2026-05-29.md`.

## Оценка карточек

- `точное` - товар, целевой регион, сумма от 30 000 рублей и активный срок подтверждены.
- `вероятное` - товар и регион подтверждены, но не указана сумма или срок подачи.
- `ручная проверка` - товар интересен, но карточка не подтвердила регион или содержит несколько неполных полей.

Дополнительно JSON и Excel содержат `review_priority`:

- `hot` - лист `Горячие`, сильные кандидаты для первого просмотра.
- `review` - лист `На проверку`, похожие закупки с одним неполным важным полем.
- `wide` - лист `Широкий хвост`, слабые, но потенциально полезные совпадения для ручного прохода.
- `excluded` - лист `Отсеянные`, записи с понятной причиной исключения.

Публичная таблица B2B-Center не всегда показывает регион поставки и цену. Такие карточки сохраняются в `Широкий хвост` или `На проверку`, а не исключаются автоматически.

## Раскрытие первоисточника РосТендера

РосТендер используется как широкий радар, но не как конечная точка работы. После регионального и товарного фильтра парсер открывает только короткий список подходящих детальных страниц (по умолчанию не более 50), извлекает заявленный номер из публичных SEO-метаданных по явному маркеру `Закупка:`, затем делает точное сопоставление с уже собранными ЕИС/ЭТП. Если карточки ещё нет среди источников, выполняется один официальный поиск ЕИС по номеру. Только точное совпадение становится официальным номером и ссылкой; нулевой результат остаётся неподтверждённым. Положительное подтверждение перепроверяется каждые 12 часов, поэтому удалённая или ошибочная карточка не остаётся «вечной» в кэше. Внутренний номер и URL РосТендера не заменяются и остаются как provenance.

Результаты кэшируются в `data/rostender_resolution_cache.json`. Подтверждённый номер повторно не запрашивается; отсутствие номера и неудачный поиск проверяются заново через 24 часа. Ошибка обогащения не прерывает основной сбор. Лимит, задержка, тайм-аут и TTL задаются переменными `ROSTENDER_RESOLUTION_*` из `.env.example`; для аварийного отключения используется `ROSTENDER_RESOLUTION_ENABLED=0`.

## Локальные прайсы поставщиков

Коммерческие прайсы хранятся в `supplier_catalog/private/` и никогда не
коммитятся в публичный GitHub. Настройки поставщиков находятся в
`supplier_catalog/suppliers.json`, подробная инструкция — в
`supplier_catalog/README.md`.

После добавления или замены Excel-прайса индекс обновится при следующем запуске.
Его также можно пересобрать вручную и сразу проверить поиск:

```powershell
python -m tender_parser supplier-index
python -m tender_parser supplier-search --query "AIKO SL-185/2" --limit 10
```

Обычный сбор автоматически сопоставляет актуальные тендеры с подходящими
товарами. Для быстрого запроса с телефона используйте Telegram-команду
`/price <название, модель или артикул>`.

## Ручной запуск

```powershell
python -m venv .venv
.\.venv\Scripts\activate
python -m pip install -r requirements.txt
python -m tender_parser run
```

Профили запуска:

```powershell
python -m tender_parser run --profile full   # все источники, режим по умолчанию
python -m tender_parser run --profile fast   # ЕИС + ГПБ API + быстрые источники, без RTS
python -m tender_parser run --profile local  # только imports/ и documents/
python -m tender_parser run --profile rts    # только RTS-Tender для диагностики
python -m tender_parser run --profile rts-cabinet  # текущая выдача RTS из открытого Chrome-профиля
python -m tender_parser rts-add-page               # добавить текущую страницу RTS в накопитель
python -m tender_parser rts-watch                  # автосбор: следит за Chrome и добавляет страницы сам
python -m tender_parser run --profile rts-accumulated  # отчет по всем накопленным страницам RTS
```

## ЕАТ / Березка

Источник ЕАТ отключен, пока не заданы переменные окружения:

```powershell
$env:EAT_API_TOKEN="токен из ЛК ЕАТ"
$env:EAT_EXT_SYSTEM="код внешней системы из ЛК ЕАТ"
python -m tender_parser run
```

Подробная инструкция и безопасный helper для `.env`: `docs/EAT_TOKEN_SETUP.md`.

По умолчанию токен отправляется в заголовке `Authorization: Bearer ...`. Если в ЛК/документации указан другой заголовок, можно переопределить `EAT_AUTH_HEADER` и `EAT_AUTH_SCHEME`.

Можно хранить локальные настройки в `.env`:

```powershell
copy .env.example .env
python -m tender_parser check-env
```

`.env` добавлен в `.gitignore`; в Git хранится только `.env.example` с пустыми значениями. Команда `check-env` показывает только `configured`/`missing` и не печатает секреты.

## Региональные закупки малого объема

- Республика Крым подключена через открытый JSON [официальной витрины](https://zrk.rk.gov.ru/smallpurchases/). Парсер забирает только статусы «Опубликовано» и «Подача заявок», читает страницы, удаляет дубли и использует прямую ссылку РТС/ГПБ, если витрина ее опубликовала.
- Для Севастополя используется [актуальный адрес витрины](http://rks.sevzakaz.ru/zakupki-malogo-obema/oos-rks-001-001) региональной контрактной системы. Устойчивый открытый API пока не подтвержден, поэтому адаптер честно показывает статус `skipped`, а не ложный успешный ноль. Назначение этой подсистемы и порядок участия также описаны на [официальном портале поддержки предпринимательства Севастополя](https://mb92.ru/news/zakupki_malogo_obyema/).
- Резерв для Севастополя: выгрузить открытый реестр в CSV/XLSX по шаблону `docs/templates/sevastopol_zmo_import_template.csv` и положить его в `imports/`. Общий импорт обрабатывается при каждом запуске, включая профиль `fast`.

## RTS-Tender

RTS-Tender выделен как отдельный стратегический контур. Публичный RTS-market использует focused `RTS_SEARCH_QUERIES` и пишет отдельные health-строки по endpoint-ам: Rosatom, общий RTS-market, Симферополь и Ялта. В профиле `full` он опрашивается непосредственно; быстрый ежедневный профиль `fast` не ждёт RTS, а читает его последний успешный фоновый снимок.

Рекомендуемое расписание: отдельный RTS в 02:30, основной `fast` в 08:00. Установить или обновить фоновую задачу Windows:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Настроить_фоновый_RTS.ps1 -Time 02:30 -TimeoutMinutes 45
```

Задача `Tender Parser RTS Background` работает от `SYSTEM`, не зависит от входа пользователя, имеет жёсткий лимит 45 минут, `StartWhenAvailable`, требует сеть, не запускает второй экземпляр и при ошибке повторяется три раза с интервалом 30 минут. Она выполняет только:

```powershell
.\.venv\Scripts\python.exe -m tender_parser rts-refresh --base-dir .
```

Успех атомарно обновляет `data/rts_last_good.json`; состояние каждого запуска хранится в `data/rts_background_state.json`, журнал — в `logs/rts_background.log`. Ошибка, CAPTCHA, тайм-аут или подозрительно пустой ответ не стирают последний непустой снимок. При частичном ответе обновляются успешные endpoint-ы, а данные проблемного endpoint-а сохраняются со своей прежней датой свежести. Частичный результат намеренно возвращает ненулевой код, чтобы Планировщик повторил сбор, но уже найденные данные при этом не теряются. Следующий `fast`-запуск объединяет свежие сегменты снимка с остальными площадками и уже тогда обновляет общую БД, Excel, Google Sheets и Telegram. Каждый endpoint старше семи суток перестаёт импортироваться независимо от остальных и помечается `skipped`; порог можно изменить через `RTS_BACKGROUND_MAX_SNAPSHOT_AGE_HOURS`.

Проверка задачи и последнего состояния:

```powershell
Get-ScheduledTask -TaskName 'Tender Parser RTS Background' | Format-List TaskName,State
Start-ScheduledTask -TaskName 'Tender Parser RTS Background'
Get-Content .\data\rts_background_state.json
Get-Content .\logs\rts_background.log -Tail 30
```

Для личного кабинета добавлен Chrome-режим: `Открыть_RTS_кабинет_Chrome.bat` открывает отдельный профиль, вы входите вручную, затем `Собрать_RTS_кабинет.bat` читает текущую видимую выдачу и прогоняет ее через общий отчет. Подробно: `docs/RTS_CABINET_BROWSER_MODE.md`.

## Ограничения первой версии

- Основной автоматический режим работает с публичными страницами без авторизации; RTS-кабинет работает отдельно через ручной вход в Chrome.
- Публичный режим проверяет ЭТП ГПБ, Росэлторг, Заказ РФ и единый поиск Сбербанк-АСТ, Tender.Pro API, Торги82 JSON, малые закупки Крыма, B2B-Center, ЕАТ при наличии токена, ЕИС `zakupki.gov.ru`, Rostender и несколько RTS-market источников. Адаптер Севастополя остается диагностическим до подтверждения публичного API.
- ЕИС подключен через публичную HTML-выдачу и дает основной прирост по 44-ФЗ/223-ФЗ; Python использует системное хранилище сертификатов Windows, а системные proxy-настройки для ЕИС отключены из-за прежних долгих таймаутов.
- Перед фильтрацией высокоуверенные дубли между ЕИС и агрегаторами объединяются, с приоритетом официальной карточки ЕИС.
- Торги82 подключен через публичный JSON endpoint последних процедур; поиск/пагинация требуют дальнейшего разбора GWT-запросов.
- ЭТП ГПБ читается через текущий публичный JSON API; отключённая площадкой RSS-лента больше не используется.
- Не подает заявки автоматически.
- Не обходит капчу и закрытые разделы; если RTS блокирует публичные или кабинетные страницы, старый отчет не перезаписывается ошибочной пустотой.
- RTS cabinet mode читает только уже открытую пользователем выдачу в авторизованном Chrome-профиле.
