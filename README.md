# Парсер закупок и тендеров

Парсер ищет публичные актуальные закупки по заданным категориям, фильтрует их по регионам, сумме от 30 000 рублей и стоп-темам, сохраняет историю в SQLite и выгружает Excel.

## Запуск

Двойной клик по файлу:

```text
Запустить_парсер.bat
```

После завершения откроется `exports/latest.html`.

Быстрые кнопки:

- `Запустить_локальные_выгрузки.bat` - обработать только `imports/` и `documents/`, без сетевых площадок.
- `Диагностика_RTS.bat` - проверить только RTS-Tender и записать его health/report.
- `Открыть_RTS_кабинет_Chrome.bat` - открыть отдельный Chrome-профиль для ручного входа в RTS.
- `Собрать_RTS_кабинет.bat` - собрать текущую видимую выдачу RTS-кабинета через `--profile rts-cabinet`.
- `Автосбор_RTS_кабинета.bat` - запустить автосбор: окно висит в фоне, вы просто листаете выдачу RTS в Chrome, каждая страница добавляется в накопитель сама, а в углу страницы RTS виден бейдж «Накопитель RTS: N строк». Остановить - Ctrl+C или закрыть окно. Если открыть вкладку поиска `rts-tender.ru/poisk`, автосбор сохранит ее вёрстку в `diagnostics/` - по этим снапшотам настраивается парсер поиска по всем ЭТП.
- `Добавить_страницу_RTS.bat` - разово добавить текущую видимую страницу RTS-кабинета в накопитель (ручная альтернатива автосбору; дубли по номеру закупки не создаются).
- `Отчет_по_накопленному_RTS.bat` - прогнать все накопленные страницы RTS через общий отчет (`--profile rts-accumulated`).
- `Поиск_RTS_другие_площадки.bat` - открыть сохраненный поиск RTS по всем ЭТП в рабочем Chrome-профиле и сразу запустить автосбор: листаете результаты поиска, карточки с любых площадок (ЕАТ, B2B и др.) сами падают в тот же накопитель с источником `rts-poisk`.

## Ручные выгрузки и документы

Для максимального охвата можно подмешивать выгрузки из личных кабинетов и площадок без отдельной интеграции:

- положите CSV/XLSX/XML-файлы в папку `imports/`;
- шаблоны лежат в `docs/templates/import_template.csv` и `docs/templates/rts_export_template.csv`;
- поддерживаемые колонки: название, ссылка, номер, заказчик, регион, сумма, срок подачи, дата публикации, источник, описание;
- положите доказательства в папку `documents/`: TXT, CSV, XML, JSON, HTML, XLSX, DOCX, PDF;
- при запуске парсер прочитает `imports/`, добавит источник `ImportFolderSource` в `run_report.json`, затем проверит `documents/` и заполнит поля `detail_status`, `document_matches`, `delivery_region_evidence`, `source_confidence`.

PDF читается по текстовому слою; если это скан-картинка без распознанного текста, его нужно предварительно прогнать через OCR или сохранить как TXT. Реальные кабинетные выгрузки и документы не коммитятся: `imports/` и `documents/` добавлены в `.gitignore`.

## Автозагрузка документов ЕИС

Для новых подходящих закупок ЕИС парсер умеет открыть вкладку «Документы» и сохранить публичные вложения в `downloads/eis-zakupki/<номер закупки>/`. В локальном `.env` включите:

```text
DOWNLOAD_TENDER_DOCUMENTS=1
DOWNLOAD_MAX_TENDERS=10
DOWNLOAD_MAX_DOCUMENTS_PER_TENDER=10
DOWNLOAD_MAX_FILE_MB=25
```

Повторно существующие файлы не скачиваются. Итог каждого запуска записывается в `downloads/download_report.json`. Ссылки принимаются только из публичного файлового хранилища `zakupki.gov.ru`, проверка TLS не отключается.

## Уведомления Telegram

Каждый запуск всегда создаёт локальный текст `exports/notification.txt`. Для Telegram заполните в `.env`:

```text
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=
TELEGRAM_MAX_ITEMS=10
```

Если Telegram временно недоступен, новые карточки остаются в SQLite-очереди и повторно отправляются при следующем запуске. Токен не выводится в консоль и не попадает в Git.

## Ежедневный сбор

Для фонового запуска без окна есть `run_tender_parser_silent.bat`: лог будет записываться в `logs/daily.log`.

Чтобы зарегистрировать ежедневную задачу Windows на 08:00, один раз запусти PowerShell из папки проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Настроить_ежедневный_запуск.ps1
```

По умолчанию ежедневный запуск использует профиль `fast`: он включает ЕИС, текущий JSON API ГПБ и другие быстрые публичные источники, но не ждёт captcha-источники RTS. Полный режим можно включить явно:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Настроить_ежедневный_запуск.ps1 -Profile full
```

Другое время задается так:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Настроить_ежедневный_запуск.ps1 -Time "07:30"
```

Задача Windows запускается при первой возможности, если компьютер был выключен в назначенное время, и ждёт доступного сетевого подключения. Дополнительно она проверяет пропущенный запуск через две минуты после входа пользователя в Windows. Успешный запуск за расчётные сутки повторно не выполняется, а параллельные экземпляры блокируются.

При критической ошибке сбора или Telegram задача повторяется до трёх раз с интервалом 15 минут. Неотправленные Telegram-карточки остаются в SQLite-очереди и уходят при успешном повторе. Состояние предохранителя хранится в `data/scheduler_state.json`, его журнал — в `logs/scheduler.log`.

## Настройка словаря без программирования

Основные настройки поиска находятся в `config/Настройки_поиска.xlsx`. Парсер перечитывает этот файл перед каждым запуском. В нём можно:

- добавлять категории и ключевые слова;
- включать и отключать поисковые запросы;
- добавлять стоп-слова;
- выбирать регионы;
- менять минимальную сумму.

Для отключения строки выберите `Нет` в столбце `Активно`. Если файл отсутствует или повреждён, запуск не падает: используется встроенный словарь, а причина выводится в лог.

## Результаты

- `data/tenders.db` - локальная история закупок.
- `exports/tenders_YYYY-MM-DD.xlsx` - Excel с листами `Дашборд`, `Новые`, `Горячие`, `На проверку`, `Широкий хвост` и `Отсеянные`. Дашборд показывает KPI, разбивку по источникам и категориям с графиками, скоро закрывающиеся, топ причин отсева, топ горячих и здоровье источников. Новизна тендера определяется по базе `data/tenders.db` (ключ площадка+номер): впервые увиденные и впервые ставшие подходящими получают метку `🆕` в колонке `новый` на всех листах и попадают на лист `Новые`; повторно спарсенные вчерашние тендеры не дублируются и метку не получают. Колонки `мой_выбор` и `комментарий` переносятся из предыдущего файла автоматически, отмеченные ✅/🤔 собираются на листе `Мой отбор`. Листы данных: автофильтр по всем колонкам, закрепленные приоритет/срок/название, раскраска строк по приоритету, подсветка `дней_до_срока` (красный - 2 дня и меньше, желтый - неделя), кликабельные названия, суммы и сроки как настоящие числа/даты для сортировки, колонка `мой_выбор` с выпадающим списком (Беру / Думаю / Мимо) и `комментарий` для ручного отбора.
- `exports/latest.json` - JSON для будущей CRM с подходящими закупками и кандидатами на ручную проверку, включая поле `review_priority`.
- `exports/latest.html` - человекочитаемый браузерный отчет для ручного просмотра: приоритеты, ссылки, регион/сумма/срок, evidence и здоровье источников.
- `exports/new_tenders.json` - только впервые увиденные подходящие закупки и кандидаты на проверку; основной файл для ежедневной CRM-очереди, отсортированный по приоритету.
- `exports/notification.txt` - краткая человекочитаемая сводка новых закупок для уведомления.
- `exports/run_report.json` - здоровье источников: статус, число карточек, время запроса, ошибка или причина пропуска.
- JSON и Excel содержат enrichment-поля: `detail_status`, `document_matches`, `delivery_region_evidence`, `source_confidence`.
- Публичные источники: ЕИС `zakupki.gov.ru`, ЭТП ГПБ, Росэлторг, Заказ РФ, Сбербанк-АСТ, Tender.Pro API, Торги82 JSON, B2B-Center, `rostender.info` и RTS-market с диагностикой по каждому endpoint.
- ЕАТ/Березка подключается как интеграционный API-источник при наличии токена из личного кабинета.
- Исследование следующих ЭТП для подключения: `docs/etp_source_research_2026-05-29.md`.

## Оценка карточек

- `точное` - товар, целевой регион, сумма от 30 000 рублей и активный срок подтверждены.
- `вероятное` - товар и регион подтверждены, но не указана сумма или срок подачи.
- `ручная проверка` - товар интересен, но карточка не подтвердила регион или содержит несколько неполных полей.

Дополнительно JSON и Excel содержат `review_priority`:

- `hot` - лист `Горячие`, сильные кандидаты для первого просмотра.
- `review` - лист `На проверку`, похожие закупки с одним неполным важным полем.
- `wide` - лист `Широкий хвост`, слабые, но потенциально полезные совпадения для ручного прохода.
- `excluded` - лист `Отсеянные`, записи с понятной причиной исключения.

Публичная таблица B2B-Center не всегда показывает регион поставки и цену. Такие карточки сохраняются в `Широкий хвост` или `На проверку`, а не исключаются автоматически.

## Ручной запуск

```powershell
python -m venv .venv
.\.venv\Scripts\activate
python -m pip install -r requirements.txt
python -m tender_parser run
```

Профили запуска:

```powershell
python -m tender_parser run --profile full   # все источники, режим по умолчанию
python -m tender_parser run --profile fast   # ЕИС + ГПБ API + быстрые источники, без RTS
python -m tender_parser run --profile local  # только imports/ и documents/
python -m tender_parser run --profile rts    # только RTS-Tender для диагностики
python -m tender_parser run --profile rts-cabinet  # текущая выдача RTS из открытого Chrome-профиля
python -m tender_parser rts-add-page               # добавить текущую страницу RTS в накопитель
python -m tender_parser rts-watch                  # автосбор: следит за Chrome и добавляет страницы сам
python -m tender_parser run --profile rts-accumulated  # отчет по всем накопленным страницам RTS
```

## ЕАТ / Березка

Источник ЕАТ отключен, пока не заданы переменные окружения:

```powershell
$env:EAT_API_TOKEN="токен из ЛК ЕАТ"
$env:EAT_EXT_SYSTEM="код внешней системы из ЛК ЕАТ"
python -m tender_parser run
```

Подробная инструкция и безопасный helper для `.env`: `docs/EAT_TOKEN_SETUP.md`.

По умолчанию токен отправляется в заголовке `Authorization: Bearer ...`. Если в ЛК/документации указан другой заголовок, можно переопределить `EAT_AUTH_HEADER` и `EAT_AUTH_SCHEME`.

Можно хранить локальные настройки в `.env`:

```powershell
copy .env.example .env
python -m tender_parser check-env
```

`.env` добавлен в `.gitignore`; в Git хранится только `.env.example` с пустыми значениями. Команда `check-env` показывает только `configured`/`missing` и не печатает секреты.

## RTS-Tender

RTS-Tender выделен как отдельный стратегический контур. Публичный RTS-market запускается в основном live-слое, использует focused `RTS_SEARCH_QUERIES` и пишет отдельные health-строки по endpoint-ам: Rosatom, общий RTS-market, Симферополь и Ялта.

Для личного кабинета добавлен Chrome-режим: `Открыть_RTS_кабинет_Chrome.bat` открывает отдельный профиль, вы входите вручную, затем `Собрать_RTS_кабинет.bat` читает текущую видимую выдачу и прогоняет ее через общий отчет. Подробно: `docs/RTS_CABINET_BROWSER_MODE.md`.

## Ограничения первой версии

- Основной автоматический режим работает с публичными страницами без авторизации; RTS-кабинет работает отдельно через ручной вход в Chrome.
- Публичный режим проверяет ЭТП ГПБ, Росэлторг, Заказ РФ и единый поиск Сбербанк-АСТ, Tender.Pro API, Торги82 JSON, B2B-Center, ЕАТ при наличии токена, ЕИС `zakupki.gov.ru`, Rostender и несколько RTS-market источников.
- ЕИС подключен через публичную HTML-выдачу и дает основной прирост по 44-ФЗ/223-ФЗ; Python использует системное хранилище сертификатов Windows, а системные proxy-настройки для ЕИС отключены из-за прежних долгих таймаутов.
- Перед фильтрацией высокоуверенные дубли между ЕИС и агрегаторами объединяются, с приоритетом официальной карточки ЕИС.
- Торги82 подключен через публичный JSON endpoint последних процедур; поиск/пагинация требуют дальнейшего разбора GWT-запросов.
- ЭТП ГПБ читается через текущий публичный JSON API; отключённая площадкой RSS-лента больше не используется.
- Не подает заявки автоматически.
- Не обходит капчу и закрытые разделы; если RTS блокирует публичные или кабинетные страницы, старый отчет не перезаписывается ошибочной пустотой.
- RTS cabinet mode читает только уже открытую пользователем выдачу в авторизованном Chrome-профиле.
