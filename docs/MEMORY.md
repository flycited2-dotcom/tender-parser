# Project Memory

Дата обновления: 2026-06-28

## Назначение

Проект `Парсинг_тендеры` - Windows-парсер публичных закупок и тендеров. Публичный режим работает без авторизации: использует быстрые открытые источники ЭТП ГПБ RSS, Tender.Pro API, Торги82 JSON, B2B-Center, ЕИС `zakupki.gov.ru`, затем Rostender как широкий рабочий источник; RTS-market оставлен резервом на случай доступности публичных страниц. ЕАТ/Березка добавлен как опциональный интеграционный источник и включается только при наличии токена из личного кабинета.

## Ключевые решения

- Запуск для пользователя: двойной клик по `Запустить_парсер.bat`.
- Ручной запуск: `python -m tender_parser run`.
- История хранится в `data/tenders.db`.
- Текущая выгрузка создается в `exports/tenders_YYYY-MM-DD.xlsx`.
- CRM-заготовка создается в `exports/latest.json`, а ежедневная дельта - в `exports/new_tenders.json`.
- `exports/run_report.json` показывает здоровье каждого источника: статус, количество карточек, длительность и сообщение об ошибке/пропуске.
- `data/`, `exports/` и `logs/` не коммитятся, потому что это локальные рабочие артефакты.
- Excel содержит листы `Новые`, `Горячие`, `На проверку`, `Широкий хвост`, `Отсеянные`.
- Карточки получают `match_confidence`: `точное`, `вероятное` или `ручная проверка`; значение хранится в SQLite, Excel и CRM JSON.
- Quality layer added: `review_priority` splits candidates into `hot`, `review`, `wide`, and `excluded`.
- JSON exports include `review_priority`; CRM can use it to process `hot` first and leave `wide` for manual sweep.
- Если срок подачи не указан, но товар, целевой регион и сумма подтверждены, карточка остается `вероятное`, а не исключается.
- `B2BCenterSource` читает разрешенную публичную таблицу торгов по товарным запросам. Карточки без региона или цены остаются `ручная проверка`.
- Матрица из 80 запросов (16 товарных групп x 5 регионов) общая для ЕИС, ЭТП ГПБ и Rostender; у каждого источника остаются собственные лимиты ошибок.
- Если все публичные источники RTS возвращают captcha/rate-limit или сетевые ошибки, старые Excel/JSON не перезаписываются.
- Обычный запуск сейчас использует верхний `CompositeSource` с первым слоем `EtpGpbRssSource`, `TenderProSource`, `Torgi82Source`, `B2BCenterSource`, `EatIntegrationSource`, `EisZakupkiSource`, `RostenderSource`; RTS запускается только если этот слой не дал данных.
- `EatIntegrationSource` пропускается без `EAT_API_TOKEN` и `EAT_EXT_SYSTEM`. По умолчанию отправляет токен как `Authorization: Bearer ...`; при необходимости настраиваются `EAT_AUTH_HEADER`, `EAT_AUTH_SCHEME`, `EAT_MAX_DETAILS`.
- Локальные секреты теперь можно держать в `.env`; файл игнорируется Git, а `.env.example` хранит только пустые placeholders.
- CLI-команда `python -m tender_parser check-env` проверяет ЕАТ-настройки и печатает только `configured`/`missing`, без значений токенов.
- RTS-Tender вынесен в отдельный foundation-документ `docs/rts_tender_foundation_2026-06-28.md`: следующий шаг - публичный RTS v2 с диагностикой endpoint-ов и кабинетный/API-режим после проверки ЛК.
- Стратегическое решение от 2026-05-30: не пытаться делать хрупкие скрейперы для каждой ЭТП подряд. ЕИС/`zakupki.gov.ru` подключен как главный широкий источник, потому что Сбербанк-АСТ, ЗаказРФ, РТС, Росселторг и другие площадки часто дублируют 44-ФЗ/223-ФЗ закупки туда. ЭТП после этого подключаются как усилители охвата и источники уникальных коммерческих/малых закупок.
- `EisZakupkiSource` использует публичную HTML-выдачу `/epz/order/extendedsearch/results.html`, query-list `EIS_SEARCH_QUERIES`, короткий `EIS_TIMEOUT_SECONDS=8`, `EIS_MAX_ERRORS=3` и `session.trust_env=False`. Последнее важно: в текущей среде системный proxy заставлял `zakupki.gov.ru` таймаутиться, а прямой запрос отдает карточки быстро.
- `CompositeSource.fetch_with_report` собирает данные и `SourceHealth` для каждой попытки; старый `fetch_keywords` сохранен для совместимости.
- Перед фильтрацией `deduplicate_tenders` склеивает только высокоуверенные дубли: нормализованное название, одинаковая цена, день дедлайна и совместимый регион. ЕИС имеет приоритет над агрегаторами.
- `TenderStorage.upsert_many` возвращает только впервые увиденные записи, чтобы `new_tenders.json` был ежедневной CRM-очередью, а не повтором полной выгрузки.
- Есть тихий launcher `run_tender_parser_silent.bat` и PowerShell-установщик `Настроить_ежедневный_запуск.ps1`; фоновые логи пишутся в `logs/daily.log`.
- 2026-06-21 создана локальная задача Windows `Tender Parser Daily`: ежедневный запуск в 08:00 (`Europe/Istanbul`), состояние `Ready`.

## Фильтры

- Минимальная сумма: от `30 000` рублей.
- Только актуальные процедуры: дедлайн подачи должен быть позже текущего времени.
- Регионы: Симферополь, Севастополь, Республика Крым, Крым, Запорожская область, Херсонская область.
- Интересующие категории: компьютерная техника и периферия, климатическая техника, бытовая техника, канцелярия/офис, электротехника и оборудование.
- Стоп-темы: ГСМ, топливо, дизель, бензин, капитальный ремонт, строительство/дороги/асфальт/ПСД, лекарства и лекарственные препараты.
- Дополнительные broad-запросы: оргтехника, офисная техника, расходные материалы, заправка картриджей, климатическое оборудование, электротовары, металлическая мебель, шкафы.
- Поиск идет не только по категориям, но и по региональным словам, чтобы ловить закупки с нестандартными названиями.
- Для Rostender задан отдельный список запросов `ROSTENDER_SEARCH_QUERIES`: МФУ, принтеры, оргтехника, картриджи, расходники, кондиционеры, канцелярия, сейфы/стеллажи по Крыму, Севастополю, Херсонской и Запорожской областям.
- По дополнительным ЭТП создано исследование `docs/etp_source_research_2026-05-29.md`. Допроверка 2026-05-30: ЕАТ имеет REST/XML API под токен, Сбербанк-АСТ и ЗаказРФ пока без публичного API и с таймаутами live-доменов. Приоритет расширения источников теперь: health-report источников, включение ЕАТ при получении токена, затем B2B-Center HTML и углубление Торги82.
- Если у тендера указан регион, но он не попадает в целевые регионы, фильтр теперь отправляет его в `Отсеянные`, а не в `На проверку`. `review` оставлен для интересных тендеров, где регион реально не указан или сумма отсутствует.

## Следующий план

Следующий практический уровень охвата: **ЕАТ по токену, RTS-Tender v2/кабинет, затем альтернативный официальный канал ЕИС и углубление B2B-Center**.

1. Проверить `.env`: скопировать `.env.example`, заполнить `EAT_API_TOKEN` и `EAT_EXT_SYSTEM`, затем запустить `python -m tender_parser check-env`.
2. Включить ЕАТ/Березку после получения токена и кода внешней системы в личном кабинете.
3. Проработать RTS-Tender по foundation-документу: сначала публичный RTS v2 с health-report, затем кабинет/API/экспорт, если ЛК дает официальный доступ.
4. Стабилизировать основной охват: проверить официальный XML/open-data канал ЕИС и альтернативный endpoint ГПБ, не полагаясь на один HTML/RSS URL.
5. Углубить B2B-Center через личный кабинет/API или подробную карточку, чтобы вытаскивать регион и цену.
6. Затем расширять уникальные ЭТП: Торги82 с пагинацией/поиском, Фабрикант, ОТС/OnlineContract.
7. Изучить реальные дубли по `run_report.json` и настроить source-priority, если появятся новые надежные официальные каналы.

## Текущие ограничения

- Личный кабинет RTS-Tender не подключен.
- Капча и закрытые разделы не обходятся.
- HTML-парсер покрыт одной fixture-формой публичной таблицы; при изменении верстки RTS может потребоваться обновить selectors.
- Матчинг однословных категорий учитывает границы слов, чтобы не ловить `монитор` в `мониторинг` и `провод` в `трубопровод`.
- ЭТП ГПБ RSS в текущей сети таймаутится, поэтому источник ограничен коротким timeout и ранним выходом после первых ошибок.
- Торги82 подключен через открытый `searchServlet`; endpoint стабильно отдает последние 20 процедур, но найденная пагинация/поиск пока игнорируются сервером вне GWT-клиента.
- ЕИС подключен через публичный HTML-поиск; это практичный рабочий слой, но позже стоит проверить официальный XML/open-data канал, если понадобится меньше HTML-зависимости.
- ЕАТ/Березка: публичный HTML закрыт captcha. Интеграционный endpoint `requestOrderList` без токена отвечает `401`; классификаторы ЕАТ скачиваются публично.
- Сбербанк-АСТ: `www.sberbank-ast.ru` и `utp.sberbank-ast.ru` из текущей сети таймаутятся; `world.sberbank-ast.ru` показывает публичный Procurement list, но это отдельная англоязычная ветка.
- ЗаказРФ: официальная инструкция подтверждает раздел `Поиск торгов`, но live-домены `www/etp/223etp/bp.zakazrf.ru` из текущей сети таймаутятся.
- ЕИС и ЭТП ГПБ остаются внешне нестабильными: их сбои теперь не скрываются и не портят остальные результаты, но для большого охвата нужен дополнительный официальный канал ЕИС либо кабинетный доступ.
