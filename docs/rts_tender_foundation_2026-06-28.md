# RTS-Tender Foundation: 2026-06-28

## Цель

RTS-Tender для нас стратегический источник: его нельзя оставлять только как аварийный fallback. При этом текущий публичный HTML-режим площадки может отдавать captcha/rate-limit, сетевые таймауты или SSL-ошибки, поэтому следующий шаг нужно делать в два слоя:

1. публичный RTS v2 с диагностикой по каждому endpoint;
2. кабинетный/API-режим после проверки доступов в личном кабинете.

Капчу не обходим, закрытые разделы без разрешенного доступа не автоматизируем, реальные токены и сертификаты в репозиторий не кладем.

## Что уже есть в коде

`RtsPublicSource` читает публичные market-страницы через `RTS_MARKET_ENDPOINTS`:

- `https://www.rosatom.rts-tender.ru/market/` -> `rts-rosatom`
- `https://zakupki-simferopol.rts-tender.ru/market/` -> `rts-zakupki-simferopol`, `region_hint=Симферополь`
- `https://yalta-zmo.rts-tender.ru/market/` -> `rts-yalta-zmo`, `region_hint=Крым`
- `https://www.rts-tender.ru/market/` -> `rts-market`

Официальная публичная витрина Rosatom RTS показывает поиск, фильтры, число актуальных лотов и таблицу процедур, то есть HTML-канал технически пригоден для чтения открытых карточек, когда площадка не блокирует запросы.

## Основные риски

- Публичные страницы RTS могут ограничивать частые запросы или отдавать captcha.
- Региональные поддомены могут таймаутиться независимо друг от друга.
- Часть 44-ФЗ/223-ФЗ процедур дублируется в ЕИС и агрегаторах, поэтому нужен приоритет официальной карточки/лучшей карточки при дедупликации.
- Личный кабинет часто завязан на сертификат, роль организации и секцию площадки; это нельзя надежно заменить HTML-парсингом без проверки в ЛК.

## Что проверить в личном кабинете RTS

1. Есть ли раздел API, интеграция, внешние системы, выгрузки, подписки или уведомления.
2. Можно ли сохранить поисковые фильтры и получать их как файл, email, RSS, XML/CSV/XLSX или API.
3. Есть ли отдельные endpoints для 44-ФЗ, 223-ФЗ, коммерческих закупок, RTS-market и малых закупок.
4. Требуются ли сертификат/КЭП, логин-пароль, OAuth, токен, cookie-сессия или код внешней системы.
5. Есть ли ограничения частоты, IP allowlist, регламент использования или договор на интеграцию.
6. Можно ли получить в карточке регион поставки, НМЦК/цену, срок подачи, заказчика, номер процедуры и ссылку на первоисточник.

## Следующая реализация RTS v2

1. Перевести RTS из общего fallback в отдельный источник с обязательным health-report по каждому endpoint.
2. Для каждого endpoint сохранять `ok`, `empty`, `blocked`, `timeout`, `ssl_error` или `error`, а также число карточек.
3. Уменьшить темп запросов и ограничить матрицу ключей для RTS: сначала высокоценные запросы по технике, периферии, климатике, канцелярии, электротоварам, сейфам/стеллажам.
4. Не падать всем отчетом, если один endpoint RTS заблокирован.
5. Если ЛК даст токен/API/экспорт, добавить `RtsCabinetSource` отдельным классом и запускать его раньше публичного RTS.
6. При дублях с ЕИС/Rostender оставлять карточку с лучшей полнотой данных и сохранять source provenance.
