# Исследование источников ЭТП для парсера

Дата проверки: 2026-05-29  
Цель: понять, какие площадки из списка можно подключить к нашему парсеру тендеров через API, RSS/выгрузку, публичный HTML или личный кабинет.

## Короткий вывод

Статус внедрения: подключены `EtpGpbRssSource`, `TenderProSource`, `Torgi82Source` и заготовка `EatIntegrationSource` для ЕАТ/Березки. ЭТП ГПБ RSS реализован, но live-запросы из текущей сети таймаутятся; Tender.Pro API отвечает стабильно; Торги82 отдает публичный JSON последних 20 процедур через `searchServlet`; ЕАТ/Березка требует токен из личного кабинета и поэтому активируется только при настройке `EAT_API_TOKEN` и `EAT_EXT_SYSTEM`.

1. Самые полезные для быстрого расширения охвата: **B2B-Center**, **ЭТП ГПБ**, **Tender.Pro**, **Фабрикант**, **Торги82**, затем **OnlineContract** и **ОТС**.
2. Самые удобные официальные источники по признакам документации: **Tender.Pro** (публичная API-документация), **ЭТП ГПБ** (RSS/API для импорта тендеров), **Фабрикант** (WSDL/API, но больше для SRM/заказчиков), **ТЭК-Торг** (SOAP-регламент с токеном).
3. Для поставщика, которому нужно искать закупки, многие API оказываются не "поиском тендеров", а интеграцией заказчика с ЕИС/ЭТП. Поэтому для CRM-воронки практичнее идти слоями: агрегаторы/публичный HTML/RSS -> официальные API там, где дают чтение процедур -> личный кабинет/экспорт там, где публичка закрыта.
4. **АСТ ГОЗ** не стоит брать в первый контур: закрытые/защищенные процедуры, доступ через аккредитацию и спецсреду, публичного парсинга по смыслу почти нет.

## Допроверка 2026-05-30: ЕАТ, Сбербанк-АСТ, ЗаказРФ

- **ЕАТ / Березка (`agregatoreat.ru`)**: главная страница из обычного HTTP-клиента возвращает captcha, но официальная инструкция по интеграции подтверждает REST/XML-сервисы. Публично доступны zip-классификаторы `eatCategorySet.zip` и `eatCategoryCatalog.zip`; метод `requestOrderList` без токена отвечает `401`. Подключена заготовка `EatIntegrationSource`: после получения токена в ЛК ЕАТ можно читать список закупочных сессий и детальные карточки через `requestOrderList` и `orderNotification`.
- **Сбербанк-АСТ (`sberbank-ast.ru`, `utp.sberbank-ast.ru`)**: основные российские домены из текущей сети стабильно таймаутятся. Официальная англоязычная ветка `world.sberbank-ast.ru` показывает публичный `Procurement list`, а инструкция поставщика описывает поиск через реестры, но публичного API для российского поиска не найдено. Пока не подключаем, чтобы не добавить хрупкий источник.
- **ЗаказРФ (`zakazrf.ru`)**: официальная инструкция подтверждает раздел `Поиск торгов`/`Торги` и поиск аукциона по параметрам, но домены `www.zakazrf.ru`, `etp.zakazrf.ru`, `223etp.zakazrf.ru`, `bp.zakazrf.ru` из текущей сети таймаутятся. Публичного API не найдено; следующий шаг - browser/network-анализ или кабинетный экспорт.

## Предлагаемый порядок подключения

1. **ЭТП ГПБ RSS**: быстро, официально, меньше риска блокировок. Нужен парсер RSS + нормализация дат/цен/регионов.
2. **B2B-Center HTML**: много актуальных коммерческих закупок, публичная выдача уже видна без кабинета.
3. **Tender.Pro API**: проверить, можно ли без платной авторизации получать список открытых процедур; если да, это будет самый чистый API-источник.
4. **Торги82 HTML**: регионально важен для Крыма/Севастополя, небольшой объем, удобно отладить.
5. **Фабрикант**: сначала выяснить, что дает demo API поставщику; если только заказческие операции, делать HTML.
6. **ЕАТ / Березка API**: получить токен в ЛК и включить `EatIntegrationSource` через переменные окружения; без токена источник не должен ходить в captcha-HTML.
7. **OnlineContract / ОТС**: делать через браузерный network-анализ, потому что публичный HTML у них сильно динамический.
8. **Росселторг / Сбербанк АСТ / ЗаказРФ / ЭТП РФ / ТЭК-Торг**: подключать после первичной пачки, либо через официальный доступ/личный кабинет.
9. **АСТ ГОЗ**: пока исключить из парсинга.

## Что нужно от владельца кабинетов

Для API-ветки нужны ответы из личных кабинетов или от поддержки площадок:

- есть ли раздел "API", "Внешние интеграции", "Токены", "WebService", "SOAP", "REST";
- можно ли получить список актуальных процедур по фильтрам поставщика: ключевые слова, регион, цена, дата окончания;
- есть ли экспорт в Excel/CSV/RSS/XML;
- тариф/стоимость доступа к API;
- ограничения частоты запросов;
- можно ли использовать данные в собственной CRM.
