# Дизайн: программа повышения качества парсинга

Дата: 2026-07-03
Статус: фаза 1 в работе, фаза 2 запланирована

## Проблема

Ревью кода 2026-07-03 показало, что конвейер архитектурно здоров (источники → enrichment → дедуп → фильтры → SQLite → экспорт), но тихо теряет или неверно отсеивает целевые тендеры:

1. Кросс-источниковый дедуп в `CompositeSource` идёт по голому `tender_number` — совпадение числовых id у разных ЭТП молча выбрасывает чужой тендер.
2. Региональный словарь без городов и падежей: карточки с регионом «г. Ялта», «Керчь», «Запорожская обл.» исключаются как «регион не целевой». Словарь продублирован в трёх местах (`config.REGION_TERMS`, `eis.REGION_VARIANTS`, `dedup.REGION_BUCKETS`).
3. Стоп-термы применяются к имени заказчика: больница с «лабораторией» в названии, покупающая МФУ, отсекается стоп-словом «лаборатория».
4. Словарь категорий цепляет ложные основы: «мышь» → «мышьяк», «щит» → «щитовидной».
5. `new_tenders.json` (CRM-дельта) видит только впервые встреченные карточки: тендер, впервые попавший без цены (excluded/wide), при появлении цены и переходе в hot никогда не попадает в дельту. Upsert перезаписывает заполненные поля пустыми при деградации источника.
6. B2B-Center/Tender.Pro в списке не дают цену/регион — 138 из 177 actionable карточек последнего full-run ушли в «широкий хвост» шумом.
7. Нет ретраев и троттлинга: один сетевой сбой убивает endpoint, 110 запросов подряд приводят к бану RTS.
8. ЕИС читается по 10 записей на запрос без сортировки по дате; ежедневный профиль `fast` вообще без ЕИС.
9. Дрейф вёрстки площадки выглядит как невинный статус `empty` — поломка селекторов может оставаться незамеченной неделями.
10. Нормализация текста/цен/дат продублирована (4 парсера цены, 6 парсеров дат), `normalize_text` не сводит `ё→е` и не чистит узкие пробелы.

## Цель

Меньше ложных исключений целевых тендеров, ноль тихих потерь на дедупе, полная CRM-дельта, устойчивость к дрейфу вёрстки и сетевым сбоям.

## Фаза 1 — точность конвейера (офлайн-проверяемо, текущий план)

План: `docs/superpowers/plans/2026-07-03-parsing-quality-phase1.md`.

- **Нормализация**: `normalize_text` сводит `ё→е`, чистит ` `/` `; `parse_price_rub` получает флаг `require_currency` и заменяет дубли в `imports` и `rts_cabinet`.
- **Словарь категорий**: общая функция `word_term_matches` в `text.py` с таблицей исключений (`монитор(?!инг)`, `мышь(?!як)`, `щит(?!овидн)`), используется фильтрами и `documents.py`.
- **Регионы**: новый модуль `tender_parser/regions.py` — канонический регион + словоформы + города (Ялта, Керчь, Евпатория, Феодосия, Мелитополь, Геническ и др.), функции `detect_region(text)` и `region_bucket(text)`. Используется фильтрами, ЕИС и дедупом; три старых словаря сходятся в один.
- **Стоп-термы**: проверяются по title + raw_text с вырезанным именем заказчика; категория/регион ищутся по-прежнему по полному тексту.
- **Дедуп**: ключ в `CompositeSource` — всегда `unique_key` (`source:number`); в `RtsPublicSource` региональные endpoint'ы с `region_hint` обходятся первыми, чтобы дубль не терял регион.
- **Хранилище**: upsert не затирает непустые customer/region/price/deadline/published_at/raw_text пустыми значениями (COALESCE); `upsert_many` возвращает не только first-seen, но и карточки, впервые ставшие actionable (excluded/None → hot/review/wide).
- **Импорты**: битая строка CSV/XLSX/XML не отбрасывает весь файл — ошибка пишется в health detail, остальные строки читаются.
- **Tender.Pro**: API-ключ читается из env `TENDER_PRO_API_KEY` (текущий ключ остаётся дефолтом), добавлен в `.env.example`.
- **ЕИС**: `recordsPerPage=_50` вместо `_10` (проверить live при следующем запуске).

Известное ограничение фазы 1: слитая из БД цена/регион не переоценивается фильтром в текущем запуске (оценка идёт по свежему снапшоту источника). Переоценка карточек из БД — фаза 2.

## Фаза 2 — охват и устойчивость (нужны live-проверки, отдельный план)

1. **Двухэтапный парсинг**: дозагрузка detail-карточек B2B-Center/Tender.Pro/Rostender для кандидатов, прошедших категорийный фильтр — заполнение цены/региона/срока, вывод из «широкого хвоста».
2. **Сетевой слой**: retry с экспоненциальным backoff на timeout, случайные паузы внутри источника, параллельный запуск независимых источников.
3. **ЕИС**: сортировка по дате публикации; исследовать официальные open-data (ftp.zakupki.gov.ru / SOAP) как замену HTML-скрейпингу; вернуть ЕИС в ежедневный профиль после стабилизации.
4. **RTS-аккумулятор** (по HANDOFF): команда «добавить текущую страницу RTS» — накопление видимых строк кабинета в SQLite с дедупом по номеру; осторожное автолистание через уже подключённый CDP.
5. **Детект тихой поломки**: статус `suspect_empty`, когда источник отдал HTTP 200 на все запросы, но распарсено 0 карточек; сохранение первого «пустого» ответа в `diagnostics/`; baseline ожидаемого числа карточек в run_report.
6. **Переоценка из БД**: после merge-upsert прогонять объединённую карточку через `evaluate_tender`, чтобы статус соответствовал слитым данным.

## Не делаем

- Обход капчи и закрытых разделов.
- Полное автоматическое листание RTS до стабилизации сети/VPN (вывод HANDOFF 2026-07-01).
- Смену словарей категорий/стоп-тем по существу (только точность сопоставления).
