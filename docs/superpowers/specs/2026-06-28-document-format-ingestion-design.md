# Document Format Ingestion Design

## Goal

Расширить локальный слой `documents/`, чтобы обычный запуск парсера автоматически читал реальные файлы ТЗ и спецификаций в форматах PDF, DOCX и XLSX, а не требовал предварительного сохранения всего в TXT/HTML/CSV/XML/JSON.

## Approach

Используем существующий `DocumentAnalyzer` и добавляем только новые readers:

- `.xlsx` читается через уже установленный `openpyxl`;
- `.docx` читается без новой зависимости как ZIP-архив с XML-документом `word/document.xml`;
- `.pdf` читается через `pypdf==6.14.2`, потому что надежный PDF text extraction без библиотеки будет слишком хрупким.

Данные после чтения проходят через текущую логику evidence extraction: товарные ключи, регионы, стоп-термины, summary и searchable_text. Поведение CLI не меняется: пользователь кладет файлы в `documents/`, запускает парсер, поля `detail_status`, `document_matches`, `delivery_region_evidence`, `source_confidence` заполняются как раньше.

## Scope

В этом инкременте не делаем OCR для сканов, не скачиваем документы с площадок, не автоматизируем кабинеты и не обходим капчи. Если PDF является картинкой без текстового слоя, он будет прочитан как пустой.

## Testing

Добавить TDD-тесты на:

- чтение XLSX из `documents/`;
- чтение DOCX из `documents/`;
- чтение PDF из `documents/`;
- отсутствие регрессий полного набора `pytest -q`.
