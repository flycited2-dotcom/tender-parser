# Deep Enrichment Core Design

## Цель

Перевести проект от простого сбора списков закупок к тендерной разведке: принимать карточки из разных источников, усиливать их данными из кабинетных выгрузок и документов, сохранять доказательства пригодности и отдавать CRM больше контекста для ручной проверки.

## Подход

Первый инкремент не подключает закрытые кабинеты напрямую и не обходит капчу. Он создает безопасное ядро:

1. расширенные поля карточки `TenderRecord`;
2. импорт файлов из папки `imports/`;
3. легкий анализ текстовых документов из папки `documents/`;
4. единый слой enrichment перед фильтрацией, хранением и экспортом.

## Новые поля карточки

- `detail_status`: состояние глубокого слоя: `not_checked`, `imported`, `documents_checked`, `enriched`.
- `document_matches`: найденные в документах/выгрузках товарные и стоп-слова.
- `delivery_region_evidence`: текстовое доказательство региона поставки.
- `source_confidence`: числовая уверенность источника от `0.0` до `1.0`.

Поля экспортируются в JSON, Excel и SQLite. Старые базы мигрируют через `ALTER TABLE`.

## Импорт из личных кабинетов

Папка `imports/` игнорируется Git. Пользователь может положить туда выгрузки из ЕАТ, RTS, B2B-Center, Фабриканта, Сбербанк-АСТ, ЗаказРФ или другой площадки.

Поддерживаемые форматы первого инкремента:

- `.csv`;
- `.xlsx`;
- простой `.xml` с элементами `tender`, `item`, `procedure` или `purchase`.

Импорт ищет синонимы колонок: название, ссылка, источник, номер, заказчик, регион, сумма, срок подачи, опубликовано, описание. Неполные карточки не падают: если есть название и ссылка/номер, они попадают в общий поток на фильтрацию.

## Документный слой

Папка `documents/` игнорируется Git. Первый инкремент анализирует `.txt`, `.csv`, `.xml`, `.html`, `.htm`, `.json` как текстовые файлы. PDF/DOCX/XLSX остаются следующим этапом, чтобы не добавлять тяжелые зависимости без отдельного решения.

Анализ документов:

- ищет товарные ключи из `CATEGORY_KEYWORDS` и `BROAD_SEARCH_TERMS`;
- ищет стоп-слова из `STOP_TERMS`;
- ищет региональные слова из `REGION_TERMS`;
- возвращает evidence для карточки.

## Enrichment Pipeline

Новый слой `TenderEnricher` работает до `evaluate_tender`:

1. получает карточки из источников;
2. добавляет импортированные карточки из `imports/`;
3. применяет доказательства из `documents/`;
4. заполняет `detail_status`, `document_matches`, `delivery_region_evidence`, `source_confidence`.

Фильтр остается главным решающим слоем. Enrichment только добавляет контекст и может помочь найти регион, если он явно найден в документах.

## Ограничения

- Реальные токены, cookie, сертификаты и кабинетные файлы не коммитятся.
- Закрытые разделы без разрешенного доступа не автоматизируются.
- Первый документный слой не парсит бинарные PDF/DOCX/XLSX.
- Если `imports/` или `documents/` пустые, обычный запуск работает как раньше.

## Проверка

- Unit tests для новых полей модели, storage, JSON и Excel.
- Unit tests для CSV/XLSX/XML import source.
- Unit tests для document analyzer и `TenderEnricher`.
- CLI test: импорт из `imports/` добавляет карточку в итоговый JSON.
