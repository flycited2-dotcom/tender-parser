# Дизайн: парсер публичных закупок РТС-Тендер

Дата: 2026-05-19

## Цель

Создать первую версию Windows-парсера для публичных закупок `rts-tender.ru`, который запускается одной кнопкой, ищет актуальные закупки по нужным регионам и товарным направлениям, сохраняет историю в локальную базу и выгружает результат в Excel.

Первая версия работает без авторизации. Личный кабинет РТС-Тендер может быть добавлен позже как отдельный источник, если публичных данных окажется недостаточно.

## Успех первой версии

- Пользователь запускает `Запустить_парсер.bat` двойным кликом.
- Парсер собирает только закупки, где еще можно подать заявку.
- В выдачу попадают закупки от `30 000 ₽`.
- Результаты фильтруются по заданным регионам, категориям и стоп-темам.
- Найденные закупки сохраняются в SQLite без дублей между запусками.
- Создается Excel-файл с подходящими и отсеянными закупками.
- Рядом создается `latest.json` для будущей интеграции с CRM.

## Область поиска

Основной сайт: `rts-tender.ru`.

Публичные разделы и поддомены РТС-Тендер рассматриваются как часть источника, если они доступны без авторизации. В первую очередь учитываются публичные страницы закупок и карточки процедур. Если обычные HTTP-запросы не дают доступ к публичной странице из-за динамической загрузки или Anti-DDoS-проверки, парсер может использовать браузерный fallback с умеренными паузами.

Fallback не должен агрессивно обходить защиту или выполнять массовые запросы. Его задача - имитировать обычный ручной просмотр публичных страниц с логированием результата.

- Крым
- Запорожская область
- Херсонская область

Региональный фильтр гибридный:

- Высокая уверенность: регион явно указан в месте поставки, регионе закупки или карточке процедуры.
- Средняя уверенность: регион найден в названии, описании или другом публичном тексте карточки.

В Excel нужно сохранять причину включения, чтобы было понятно, почему закупка попала в выдачу.

## Данные карточки закупки

Минимальный набор полей:

- дата обнаружения
- категория совпадения
- название
- номер закупки
- заказчик
- регион или место поставки
- цена
- срок подачи заявки
- статус
- ссылка
- причина включения
- причина исключения
- источник

Если поле отсутствует на публичной странице, оно сохраняется пустым, а парсер продолжает обработку.

## Хранение

Локальная база: `data/tenders.db`.

База хранит:

- все найденные закупки
- подходящие закупки
- отсеянные закупки
- дату первого обнаружения
- дату последнего обновления
- статус фильтрации
- причины включения и исключения

Уникальность закупки определяется по стабильному ключу: номер закупки, если он найден; иначе нормализованная ссылка на карточку.

## Excel-выгрузка

Папка выгрузок: `exports/`.

Имя файла: `tenders_YYYY-MM-DD.xlsx`.

Листы:

- `Подходящие` - закупки, прошедшие фильтры.
- `Отсеянные` - спорные или исключенные закупки с причиной.

После запуска `Запустить_парсер.bat` папка `exports/` открывается автоматически.

## Экспорт для CRM

Для будущей CRM создается файл `exports/latest.json` с подходящими закупками в структурированном виде. На первом этапе CRM не вызывается напрямую.

Такой формат оставляет три пути интеграции:

- CRM читает `latest.json`.
- CRM читает SQLite.
- Позже добавляется отправка через API, если в CRM появится готовый endpoint.

## Запуск

Основной запуск: `Запустить_парсер.bat`.

Сценарий запуска:

1. Проверить или создать виртуальное окружение Python.
2. Установить зависимости из `requirements.txt`, если они еще не установлены.
3. Запустить парсер.
4. Обновить SQLite.
5. Создать Excel и `latest.json`.
6. Открыть папку `exports/`.

Дополнительный запуск для терминала: `python -m tender_parser run`.

## Архитектура

Проект делится на небольшие модули:

- `tender_parser.sources.rts` - получение публичных данных РТС-Тендер.
- `tender_parser.filters` - регионы, категории, стоп-темы, сумма, активность срока подачи.
- `tender_parser.storage` - SQLite и антидубли.
- `tender_parser.exporters.excel` - Excel-выгрузка.
- `tender_parser.exporters.json` - `latest.json` для CRM.
- `tender_parser.cli` - командный запуск.
- `tender_parser.config` - словари и настройки.

Границы нужны, чтобы позже добавить второй источник, например ЕИС или личный кабинет РТС, без переписывания фильтров, базы и экспорта.

## Проверка

Минимальные тесты первой версии:

- региональный фильтр на точные и текстовые совпадения
- категории интереса
- стоп-темы, включая лекарства и ГСМ
- минимальная сумма `30 000 ₽`
- активный и истекший срок подачи
- антидубли по номеру закупки или ссылке
- создание SQLite на тестовых данных
- создание Excel на тестовых данных

Дополнительно нужен smoke test команды `python -m tender_parser run` на небольшом тестовом наборе.

## Риски

- Публичные страницы РТС-Тендер могут быть закрыты Anti-DDoS-проверкой.
- Часть закупок может находиться на поддоменах или в динамических разделах.
- Поля карточек могут отличаться между разделами РТС.
- Публичный поиск может не покрывать все закупки, доступные в личном кабинете.

Митигируем это логированием, браузерным fallback для публичных страниц и модульной архитектурой источников.

## Не входит в первую версию

- Авторизация в личном кабинете.
- Автоматическая подача заявок.
- Обход капчи или закрытых разделов.
- Полная CRM-интеграция через API.
- Парсинг документов закупки, если они требуют авторизации.
