# Первый рабочий контур тендерного дела

## Назначение

Контур обрабатывает только закупки, которые владелец уже выбрал для подробного анализа. Он не подает заявки и не подписывает документы.

## Создание дела

```powershell
python -m tender_parser case-init --case-id 123456 --title "Поставка компьютерной техники"
```

Будет создана папка `cases/123456/`:

- `case.json` — паспорт закупки, НМЦК, сроки и регион;
- `items.csv` — позиции и обязательные характеристики ТЗ;
- `offers.csv` — предложения основного и альтернативных поставщиков;
- `expenses.csv` — доставка, разгрузка, монтаж и другие расходы;
- `documents/` — документация закупки;
- `supplier_responses/` — ответы и коммерческие предложения поставщиков;
- `output/` — итоговый отчет.

Рабочие дела исключены из Git, поскольку могут содержать коммерческие и уставные документы.

## Статусы предложений

- `exact` — точный товар;
- `compliant` — полностью соответствующий аналог;
- `conditional` — условное соответствие, только ручное согласование;
- `not_compliant` — не соответствует;
- `not_found` — товар не найден.

Если в `offers.csv` нет строки с `selected=yes`, система автоматически выбирает самое дешевое предложение со статусом `exact` или `compliant`. Условный аналог автоматически не выбирается.

## Формирование отчета

Сначала выполните предварительный анализ документации:

```powershell
python -m tender_parser case-preflight --case-id 123456
```

Команда не изменяет заполненные владельцем `case.json` и `items.csv`. Она создает в `output/`:

- `preflight.md` — короткое заключение по составу документов и рискам;
- `preflight.json` — структурированный результат для будущей CRM;
- `items_draft.csv` — найденные в таблицах позиции с файлом, листом/строкой и уровнем уверенности;
- `customer_questions.txt` — черновик вопросов заказчику.

Если PDF не содержит текстового слоя, анализ ставит блокер OCR. Отсутствие ТЗ, проекта контракта или извещения также блокирует автоматический переход к поиску товара.

После проверки черновика перенесите подтвержденные позиции в `items.csv`, заполните предложения и расходы, затем сформируйте экономический отчет:

Поиск по основному поставщику запускается отдельно:

```powershell
python -m tender_parser case-products --case-id 123456 --limit 10
```

Команда использует закрытый read-only мост к уже синхронизированному каталогу I-T-P и создает `supplier_candidates.json`, `supplier_search.md` и `offers_draft.csv`. Числовые требования вида «не менее / не более» сверяются со структурированными характеристиками: явное нарушение получает `not_compliant`, полностью подтвержденный набор — `compliant`, недостаток данных — `conditional`. Исходный `offers.csv` не перезаписывается, а окончательное соответствие всегда подтверждается паспортом или спецификацией производителя.

Для подключения задайте в локальном `.env`:

```text
TENDER_SUPPLIER_API_URL=https://ваш-сайт/api/internal/tender-products
TENDER_SUPPLIER_API_TOKEN=отдельный-секрет-длиной-не-менее-32-символов
```

Подтвержденные предложения перенесите в `offers.csv`, измените статус на `exact` или `compliant` и добавьте доказательство характеристик. Затем сформируйте экономический отчет:

```powershell
python -m tender_parser case-report --case-id 123456
```

Результат: `cases/123456/output/case_report.xlsx`. В нем есть решение, позиции, все предложения, расходы, сравнение ООО/ИП, риски, вопросы заказчику, документы и чек-лист комплекта заявки.

## Следующие интеграции

1. Сопоставление обязательных характеристик ТЗ с карточками товаров.
2. Поиск альтернативных поставщиков и реестр запросов КП.
3. Подстановка утвержденных шаблонов документов.
4. Telegram-уведомления и передача статусов в CRM.

## Граница безопасности

Мост каталога предоставляет только поиск. Он не резервирует товар, не создает заказ и не подтверждает отгрузку. Черновики `items_draft.csv` и `offers_draft.csv` отделены от рабочих `items.csv` и `offers.csv`, поэтому результат автоматического извлечения или подбора не становится принятым без ручного переноса/подтверждения владельцем.
