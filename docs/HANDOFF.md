## Обновление 2026-07-04: тотальное red-team ревью и волна исправлений

Пять параллельных ревью-агентов (ядро фильтрации, HTTP-источники, хранилище/CLI, экспортёры, watcher) нашли 55 дефектов (15 blocker / 28 should / 12 nit), все доказаны исполнением; 13 контрольных проверок оркестратора совпали. Исправлено пятью коммитами (каждый — TDD, полный pytest):

- **Ядро** (`Fix core matching precision...`): «провод» больше не матчит «проводится» (шаблонная фраза красила мусор в электротехнику); падежный стем-fallback для однословных терминов («бумаги», «посуды», «ламп» теперь находятся; беглые гласные типа «розеток» — известное ограничение); вырезание заказчика из предмета — по нормализованному тексту (регистр/ё больше не ломают); лимит разрыва между стемами фразы (20 симв.) — «ремонт ... фасаде здания» не склеивается в стоп-фразу; топонимы-двойники (Крымский Вал, г. Крымск, Херсонес, Белогорск Амурский, «армянский») отсечены с сохранением «Крымской таможни»; стоп-однословники через word-matching («реализуется» ≠ «реализует», падежи стопов покрыты); битый документ не роняет enrichment; стоп-темы из документов дописываются в raw_text и режут тендер; «фен» защищён от фентанила/фенхеля, «усо» — от «усопших»; parse_price_rub понимает «млн»/«тыс».
- **Источники** (`Harden sources...`): битый .xlsx в imports/ не роняет весь сбор (BadZipFile); ISO-дедлайны с таймзоной больше не валят фильтр (tz срезается); B2B-детали не затирают известный регион сырым адресом и пустая деталь не помечает enriched; Tender.Pro принимает boolean success и не вшивает API-ключ в URL записей; ЕАТ парсит XML из bytes (уважает объявленную кодировку); карточки поиска RTS без номера/ссылки пропускаются (не схлопываются перезаписью); CSV-разделитель по заголовку, многострочные поля через StringIO, xlsx закрывается; SSLError не ретраится.
- **Хранилище/CLI** (`Commit DB after exports...`): критичное — БД фиксируется ПОСЛЕ успешных экспортов (упавший экспорт больше не теряет «новых для CRM» навсегда; до фикса: crash после коммита → тендер исчезал из new_tenders.json безвозвратно); SQLite: timeout=30с, WAL, явное закрытие соединений (WinError 32 при копировании базы устранён); merged document_matches/detail_status/evidence не затираются пустым прогоном, source_confidence — MAX; suspect_empty сравнивается только с прогоном того же профиля (профиль пишется в run_report.json); .env читается с utf-8-sig (BOM Блокнота); мусорный --now — код 2 вместо traceback.
- **Экспортёры** (`Protect user marks...`): управляющие символы из вёрсток вычищаются (IllegalCharacterError ронял весь прогон); отметки читаются по mtime из 3 последних файлов (лексикографический выбор старого fallback терял отметки), листы данных приоритетнее агрегата «Мой отбор» (правка пользователя на «Горячих» побеждает); числовые номера из Excel нормализуются (123.0 == "123"), колонка «номер» форматируется как текст; fallback-имя с повтором через uuid; javascript:-URL нейтрализуются в HTML-отчёте; NaN-цены → null в JSON и пустая ячейка в Excel; высота строк дашборда ≥ 1 строки.
- **Watcher** (`Harden RTS watcher...`): reconnect реально работает (проверка browser.is_connected() — обрыв CDP не бросает исключений, прежняя ветка была мёртвой; после возврата — пауза и переподключение); ошибки SQLite при сохранении страницы печатаются, а не глотаются (пользователь видел «сбор», которого не было); снапшоты поиска — 1 на URL, максимум 5 за сессию (был шторм ~615 МБ/час на динамике); состояние results детектится раньше слова «captcha» в контенте (тендер «Проверка безопасности...» не блокирует сбор); «выход» — по границе слова («без выходных» не признак логина); generic-строки без ссылки пропускаются (виджеты не порождали мусор с перезаписью); ISO-даты в time[itemprop] поиска поддержаны на случай смены формата.

Бэклог (осознанно отложено): (1) dedup — слияние по одинаковым длинным номерам между источниками и защита от слияния разных тендеров с одинаковым названием+ценой+днём (редкий кейс, высокий риск регрессии); (2) полная переоценка карточки из merged-строки БД после COALESCE (экспорт всё ещё показывает свежий снапшот, а не «химеру» БД); (3) «щит» матчит «информационные щиты» благоустройства — принятый риск ради электрощитов; (4) live-проверка reconnect watcher'а и бейджа при следующем сеансе Chrome.

## Обновление 2026-07-01

Работа остановлена на практическом RTS-сценарии: пользователь входит в RTS через свой Chrome-профиль, вручную ставит фильтр и открывает страницу выдачи, а парсер собирает текущие видимые строки из таблицы кабинета. ## Как продолжать

Следующий практический уровень охвата: **ЕАТ по токену, RTS-Tender кабинет/API, затем альтернативный официальный канал ЕИС и углубление B2B-Center**.

1. Получить в ЛК ЕАТ токен и код внешней системы, затем выполнить `Настроить_EAT_env.ps1 -ApiToken "..." -ExtSystem "..."`.
2. Проверить `EatIntegrationSource` live-запуском через `python -m tender_parser run --profile fast`.
3. Проверить RTS cabinet live: открыть `Открыть_RTS_кабинет_Chrome.bat`, войти вручную, открыть выдачу закупок, запустить `Собрать_RTS_кабинет.bat`, затем уточнить selectors по `run_report.json`.
4. Проверить альтернативный официальный канал ЕИС: XML/open-data или кабинетный экспорт, потому что HTML search может таймаутиться. Аналогично проверить другой endpoint ЭТП ГПБ.
5. Углубить B2B-Center через личный кабинет/API или подробную карточку, чтобы вытаскивать регион и цену.
6. Углубить Торги82: найти корректный GWT/searchServlet payload для ключевых слов и пагинации, потому что простой endpoint сейчас дает только последние 20 процедур.
7. После этого смотреть Фабрикант, ОТС и OnlineContract.
8. Для CRM читать `exports/new_tenders.json` как дельту, `exports/latest.json` как полную очередь и `exports/run_report.json` как диагностику.
9. При изменении словарей править `tender_parser/config.py` и добавлять focused tests в `tests/test_filters.py`.
10. Для быстрого прироста охвата без нового scraper брать выгрузки из кабинетов/площадок, класть их в `imports/`, а технические задания/карточки в текстовом виде - в `documents/`, затем запускать обычный `python -m tender_parser run`.
11. Для ежедневной ручной проверки сначала смотреть `exports/latest.html`; для быстрой обработки кабинетных файлов запускать `python -m tender_parser run --profile local`, для публичного RTS-разбора - `python -m tender_parser run --profile rts`, для открытой RTS-кабинетной выдачи - `python -m tender_parser run --profile rts-cabinet`.
