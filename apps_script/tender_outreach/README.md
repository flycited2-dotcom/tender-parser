# Почтовый адаптер тендерной рассылки

Это отдельный Google Apps Script для таблицы
`Тендерная рассылка — подготовка`. Он создаёт черновики, умеет отправлять только
отдельно подтверждённые production-партии и обслуживается одним почасовым
триггером.

Утверждённые владельцем тема и текст зафиксированы в
[`APPROVED_TEMPLATE.md`](APPROVED_TEMPLATE.md) и в листе `Шаблон` рабочей
Google-таблицы.

## Что разрешено текущей версией

- прочитать очередь и вывести агрегированное превью;
- после явной настройки создать не более пяти **тестовых** черновиков за запуск;
- всегда подменить реального адресата на один контрольный адрес;
- записать ID тестового черновика и событие аудита в таблицу.
- после отдельного одобрения создать не более десяти **рабочих** черновиков за
  запуск на реальные адреса; функция отправки при этом не вызывается;
- после ещё одного production-допуска отправить не более 10 подготовленных
  черновиков за запуск и не более 50 писем за день.

## Одновременные предохранители тестового черновика

Все условия обязательны:

1. script property `TENDER_OUTREACH_TEST_MODE` равна строке `true`;
2. задан `TENDER_OUTREACH_TEST_RECIPIENT`;
3. задан проверенный в Gmail адрес `TENDER_OUTREACH_FROM_ALIAS`;
   для ответов можно задать `TENDER_OUTREACH_REPLY_TO`;
4. кампания имеет статус `тест`, флаг одобрения `TRUE`, дату одобрения и фразу
   `TEST_DRAFTS_APPROVED` в комментарии;
5. тема и тело письма заполнены, тема не начинается с `[ЗАБЛОКИРОВАНО]`;
6. строка имеет решение `ready_for_campaign_review`, статус `в очереди`,
   `Одобрено=TRUE`, `Автоотправка=FALSE` и пустой ID черновика;
7. адрес отсутствует в глобальном листе `Стоп-лист`.
8. `Статус согласия=подтверждено`, заполнены допустимое основание обращения,
   подтверждение и дата согласия. Публичный email сам по себе не считается
   подтверждением.

## Предохранители рабочих черновиков

К тестовым условиям добавлен отдельный, не пересекающийся контур:

1. script property `TENDER_OUTREACH_WORKING_DRAFTS_MODE` должна быть равна
   строке `true`;
2. кампания должна иметь статус `одобрена`, флаг одобрения `TRUE`, дату
   одобрения и фразу `WORK_DRAFTS_APPROVED` в комментарии;
3. каждая строка по-прежнему требует `Одобрено=TRUE`, `Автоотправка=FALSE`,
   подтверждённое основание обращения и отсутствие адреса в стоп-листе;
4. один email не может получить два черновика, если ID черновика уже записан в
   другой строке;
5. лимит кампании применяется дополнительно к жёсткому пределу 10 черновиков за
   запуск;
6. на этом этапе создаётся только Gmail-черновик; `Автоотправка` остаётся
   выключенной до отдельной проверки черновика.

## Предохранители production-отправки

Все условия обязательны одновременно:

1. property `TENDER_OUTREACH_PRODUCTION_MODE` равна строке `true`; для
   автоматического запуска дополнительно требуется
   `TENDER_OUTREACH_SCHEDULER_MODE=true`;
2. кампания имеет статус `одобрена`, флаг одобрения, дату и фразу
   `PRODUCTION_SEND_APPROVED` в комментарии;
3. строка имеет рабочий черновик, `Одобрено=TRUE`, `Автоотправка=TRUE`,
   подтверждённое основание обращения и пустые дату/ID отправки;
4. непосредственно перед отправкой повторно проверяется глобальный стоп-лист;
5. применяются лимиты кампании, property партии, жёсткий предел 10 писем за
   запуск и 50 писем за день;
6. планировщик учитывает дни и окно отправки из листа `Кампании`;
7. после отправки одной операцией записываются статус, дата, ID сообщения,
   ID цепочки и событие аудита. Повторная отправка той же строки блокируется.

## Чего в этой версии нет

- автоматического включения кампании;
- обхода глобального стоп-листа;
- отправки тестового письма реальному потенциальному заказчику;
- автоматического перевода публичного контакта в состояние, разрешающее письмо.

Черновик создаётся одновременно в текстовой и HTML-версии. URL сайтов в HTML
преобразуются в явные ссылки `<a href="...">`, поэтому их кликабельность можно
проверить в тестовом письме до любого рабочего запуска.

Для черновиков используется Advanced Gmail API с явным OAuth scope
`gmail.compose`. Стандартный `GmailApp.createDraft` намеренно не используется,
поскольку он запрашивает избыточный scope `mail.google.com`, включающий чтение и
безвозвратное удаление всей почты. Таблица ограничена scope
`spreadsheets.currentonly`; скрипт дополнительно проверяет ID привязанной таблицы.

Тема, текст, подпись и контрольный адрес согласованы. Код развёрнут 24.08.2026
только в отдельном привязанном проекте `Тендерная рассылка`; исходный HoReCa-проект
не изменён. После развёртывания подтверждено отсутствие установленных триггеров.

## Унаследованный скрипт копии

Копирование старой HoReCa-таблицы сохранило её привязанный проект Apps Script и
пользовательское меню `Рассылка`. Проверка проекта новой таблицы 24.08.2026
показала **0 установленных триггеров**; в журнале были только простые запуски
`onOpen` при открытии таблицы. Перед тестированием этот унаследованный код нужно
заменить текущим адаптером целиком. Старое меню и старые функции нельзя оставлять
рядом с новым контуром.
